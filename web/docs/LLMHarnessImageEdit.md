# API图片编辑

使用自己配置的图片服务编辑主图，可添加参考图和蒙版。保留原 mxwq 编辑节点的批次编辑、并发、进度预览和断点续作功能，来源与「LLM 远程回复」共用。

## 配置来源

点击 **添加 / 编辑来源**，在 ComfyUI 所在电脑弹出的窗口中填写来源名称、Endpoint、Key 和图片模型，保存后点击 **刷新来源**。Endpoint 例如 `https://example.com/v1`，节点自动追加 `/images/edits`。

**接口兼容范围**：本节点沿用原节点的 JSON 编辑协议，发送 `images: [{"image_url": "data:image/png;base64,..."}]`，有蒙版时发送 `mask: {"image_url": "data:image/png;base64,..."}`。服务必须支持这种协议；仅支持 multipart 文件上传的图片编辑接口不能直接使用本节点。响应支持 `data[0].b64_json` 或 HTTPS 图片地址 `data[0].url`。

来源管理里的「API 格式」仅用于文字节点，不改变本节点的图片协议。Key 不写入工作流。修改共用来源会影响所有使用该来源的节点，需要独立参数时请新建来源。

## 主图与参考图

- **输入图像1** 是主图，一个批次里的每张主图分别提交一次编辑请求。
- 连接图片后会自动增加输入口，最多 100 路。其余输入口为附加图片，请在提示词中明确用途；服务实际允许数量可能更少。
- **固定参考关闭**：按批次序号配对。例如主图有 A1、A2，参考有 B1、B2，则两次请求分别发送 A1+B1 和 A2+B2。参考批次较短时，缺少的位置不发送该参考图。
- **固定参考开启**：所有主图共用每个参考输入口的第一张图。例如两次请求发送 A1+B1 和 A2+B1。
- 未连接或缺少的参考图会跳过，请求中的图片编号随之连续排列。
- **known_mask**：可选，与主图尺寸一致，按主图批次序号配对，缺少时不发送。数值直接作为蒙版 PNG 的 Alpha（0 为透明、1 为不透明）；服务如何解释编辑区域取决于其协议。固定参考选项不改变蒙版配对。

## 参数和输出

- **prompt**：编辑要求，说明各图片用途及需要保留的内容。
- **size**：请求输出尺寸，`auto` 由服务决定。
- **quality**：`auto` 不发送质量字段，其余值直接发送。
- **并发请求数**：同时发送的主图编辑请求数量，1～8。每张主图单独请求，限流时可调为 1。
- **timeout_seconds**：连接最多等待 20 秒，此参数控制读取响应时连续收不到数据的等待时间，不是整批任务的总时限。
- **IMAGE**：输出执行列表，每一项是对应输入执行项处理后的图片批次。批次内按主图顺序排列，不按网络完成顺序排列；返回尺寸不一致时等比缩放并补黑边至该批次首张图片尺寸。

输入执行列表时，按 ComfyUI 的短列表复用末项规则配对各项，再在每项内部逐张编辑主图。固定参考针对每个执行项内部的图片批次。

## 断点续作和重新生成

成功图片立即保存到临时预览目录，并备份至 `ComfyUI/user/llm_harness_image_resume`。进度和预览会逐步更新。

- **重新生成关闭**：全部输入通过 SHA-256 匹配后，复用本次 ComfyUI 启动期间的成功图片。匹配包括所有图片口的原始像素、蒙版、参考模式、提示词、模型、来源、地址、Key、尺寸、质量、超时和并发数；相同输入可跨同类节点复用。失败后保持输入不变重跑，只补做缺失项。
- **重新生成开启**：每次运行新建一轮，成功图片逐张更新缓存；失败项保留先前成功缓存，旧备份保留。想复用成功图片时，先关闭此开关。
- 出现失败后停止派发剩余任务，已经发出的请求仍可能完成并保存。超时请求也可能已被服务处理，请核对服务记录再重跑。

图片与其他生成式节点共用内存缓存，以压缩 PNG 保存，不长期占用显存。命中时恢复预览和完成进度；Temp 预览被删除后也能重新创建。

**重启 ComfyUI 会清空自动复用记录，下一次运行会重新请求。** 磁盘备份按启动会话分开保存，重启后仍可手动查看图片，但不会自动加载上次启动的结果。备份不会随临时预览清理而消失，长期使用会占用磁盘；确认不需要时可手动清理对应备份。原 mxwq 节点及其缓存不受影响。
