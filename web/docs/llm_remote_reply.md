# LLM 远程回复

调用本地配置的远程文字或视觉模型，支持 Chat Completions、Responses、Anthropic Messages，流式展示文本。可单独生成回复，也可与 [布尔条件返回](LLMHarnessBooleanReturn.md) 组成“生成 → 校验 → 反馈重试”流程。

节点 ID：`llm_remote_reply`；分类：`llm_harness`。

## 第一次使用 / 配置来源

1. 点击 **＋ 添加 / 编辑连接**，在 ComfyUI 所在电脑填写连接名称、Endpoint、API Key、接口格式和模型 ID。多个模型名称以英文逗号分隔。
2. Chat Completions / Responses 的 Endpoint 填基础地址，例如 `https://example.com/v1`，节点分别追加 `/chat/completions` 或 `/responses`。Anthropic Messages 使用 `/v1/messages`；基础地址已以 `/v1` 结尾时只追加 `/messages`。
3. 保存并刷新页面，选择连接、模型，填写提示词，将 `回复文本` 接文本处理节点。视觉模型可连接图片。

来源管理与图片 API 节点共用。接口格式、模型图片能力、推理参数、输出长度与费用以实际服务为准。API Key 保存于本机 `data/connections.json`，不写入工作流；请妥善保管配置文件。

## 参数和输出

### 输入

| 参数 | 描述 | 数据类型 | 必需 |
| --- | --- | --- | --- |
| `连接` | 已配置连接；初始值为按名称排序的第一项。未配置时显示提示，不能实际请求 | COMBO | 是 |
| `模型` | 模型 ID；默认来自初始连接的首个模型，前端按当前连接过滤选项 | COMBO | 是 |
| `提示词` | 用户请求正文，多行，默认空；图片与此文本放入同一用户消息 | STRING | 是 |
| `系统提示词` | 默认空；非空时用 system 消息、Responses instructions 或 Anthropic system 发送 | STRING | 是 |
| `思考强度` | `关闭`（默认）、`低`、`中`、`高`；需服务及模型支持 | COMBO | 是 |
| `温度` | 默认 `0.7`，控件范围 0～2；Responses / Anthropic 开启思考时不发送温度 | FLOAT | 是 |
| `最大输出长度` | 默认 `4096`，控件范围 1～200000；服务 token 上限，不是字符数量 | INT | 是 |
| `超时（秒）` | 默认 `180`，控件范围 1～1200；网络连接及阻塞读写等待超时，不是整条回复总时限 | INT | 是 |
| `图片1` … `图片100` | 可选，连接后自动增长，最多 100 个普通口。每口 IMAGE 批次全部参与该次请求；执行列表按项配对 | IMAGE | 否 |
| `列表合并图片` | 可选，整个执行列表及每项图片批次按顺序合并到同一次请求，允许不同尺寸 | IMAGE | 否 |
| `强制重新请求` | 默认 `false`；关闭时复用会话缓存，开启时重新请求并在成功后更新缓存 | BOOLEAN | 否 |

### 输出

| 输出名称 | 描述 | 数据类型 |
| --- | --- | --- |
| `回复文本` | 完整回复按请求顺序形成执行列表，下游默认逐项处理；只请求一次时为一项。此输出不代表通过了业务校验 | STRING |
| `调度` | 与回复逐项对应的运行时调度对象，直接连接“布尔条件返回”的 `调度输入`；携带请求、图片、回复和重试历史，不是文本或 JSON | LLM_HARNESS_SCHEDULE |

原回复端口仍为索引 `0`，调度追加在索引 `1`。不连接调度时保持原有行为，不准备重试上下文。

## 示例：生成可校验的记录

系统提示词填 `只返回 JSON，不添加解释。`；提示词填 `输出 [{"id":"A","count":2}]，id 必须是非空字符串，count 必须是整数。`。

1. `回复文本` 接 `解析并校验 JSON 记录数组`（来自 `comfyui-liuxinyu-packs`）的 `输入文本`，规则填 `{"id":"nonempty_string","count":"integer"}`。
2. `调度` 直接接 `布尔条件返回` 的 `调度输入`。
3. 校验器的 `校验通过`、`错误信息` 接返回节点的同类输入，重试上限填 `2`。
4. 后续处理接返回节点的 `回复`。首次通过时重试次数为 `0`；首次失败、第二次通过时为 `1`。需要数组时，在返回节点之后再解析最终文本。

完整连接表和失败示例见 [布尔条件返回](LLMHarnessBooleanReturn.md)。校验器必须返回 false 和错误说明，不能先抛异常；记录数组校验器只检查字段和类型，不检查数值范围。

## 图片、执行列表与顺序

按普通图片口编号、各口批次顺序、合并列表顺序及内部批次顺序发送。图片保持输入宽高，编码为 PNG，不在本地缩放；服务端可能自行缩放或拒绝超限输入。

提示词或普通图片口等带执行列表时，按最长列表逐项请求，短列表复用末项；合并图片口不参与配对，每次携带完整列表。任意参与配对的输入为空执行列表时，不发送请求，两个输出均为空执行列表。

“布尔条件返回”每轮只接收一条回复，多项回复请先在外层分包。单个图片批次或合并列表可有多张图片，只要形成一个请求。更多示例和旧图片口兼容规则见 [图片输入专题](../../docs/ImageInputs.md)。

## 接口请求与响应

| 格式 | 主要请求字段 | 读取的响应 |
| --- | --- | --- |
| Chat Completions | `messages` 含 system、user；图片为 `image_url` data URL；发送 `temperature`、`max_tokens`，思考开启时增加 `reasoning_effort` | `choices[0].message.content`；流式文本 delta |
| Responses | `input` 中使用 `input_text`、`input_image`；系统用 `instructions`；长度用 `max_output_tokens`；思考开启用 `reasoning.effort`，关闭发送温度 | message 内容的 `output_text` / `text`，或顶层 `output_text`；流式 output text delta |
| Anthropic Messages | `messages` 中图片为 base64 image 块；系统用 `system`；长度用 `max_tokens`；思考开启用 adaptive thinking 和 effort，关闭发送温度 | `content` 中 text 块；流式 text delta |

请求开启流式，也接受服务直接返回普通 JSON。流式接口需符合对应事件格式和结束信号；不完整的流不会作为成功结果交给下游。只处理文字回复，不实现工具调用执行或 JSON Schema 强制输出。

重试保留初始用户消息与图片，按顺序追加每轮 assistant 回复和 user 错误反馈。Responses 历史回复使用 `output_text`，反馈使用 `input_text`。历史不写入系统提示词，不丢弃原始图片；服务需要支持对应格式的多轮对话。

## 缓存与重新生成

首次请求沿用 [会话缓存](../../docs/GenerationCache.md)：来源、地址、Key、API 格式、模型、文本、参数、图片内容和顺序参与 SHA-256，节点 ID 与强制开关不参与。A→B→A、同类节点及执行列表可复用。成功文本保留至进程退出，失败和中断不覆盖已有结果。

这里的“成功”指 API 返回完成，不代表通过业务校验。调度不加入全局缓存，每次为当前执行重新准备。校验失败后的重试始终发新请求，不读取或覆盖首次回复缓存。再次排队从计数 0 开始；如需替换原始回复，开启 `强制重新请求`。

未连接调度时命中缓存跳过图片编码；连接调度时可能需要编码 PNG，确保修正请求携带原图片，不长期保留输入 GPU 张量。缓存只在当前进程有效，重启后清空。

## 超时和错误处理

`超时（秒）` 控制连接及阻塞读写，流式接收期间仍适用；持续收到 token 或心跳时总时长可超过此值。本地图片编码不计入网络超时，多次重试的每次请求分别使用此设置。

| 现象 | 检查方法 |
| --- | --- |
| 未找到连接或未配置模型 | 检查本机连接配置，刷新页面重新选择 |
| HTTP 错误或无法解析响应 | 核对基础地址、接口格式、模型权限及实际响应 |
| 回复格式不合要求 | 将返回 false 的校验子流接布尔条件返回；提示词本身不构成强制校验 |
| 流在结束前断开 | 检查代理和服务日志；不完整文本不作为结果，重新排队可能再次计费 |
| 超时或取消 | 不自动作为布尔失败重试，也不保证服务端已取消，请核对服务记录 |
| 面板显示多轮文本 | 面板追加生成与重试文本，最终通过的结果从“布尔条件返回”读取 |

## 开发与验证

根 `__init__.py` 继续从 `LLMRemoteReply.define_schema()` 生成注册映射，图片输入延续本包原有前端扩展。帮助文件按节点 ID 命名，README 提供入口。

`tests/test_image_inputs.py` 验证图片、列表、缓存和接口行为；`tests/test_boolean_return.py` 验证实际执行器中的校验反馈。测试使用模拟接口。更新 Python 后需要重启 ComfyUI，再刷新页面加载新增节点和端口。
